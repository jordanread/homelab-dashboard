Caddy

The harbour master — automatic HTTPS reverse proxy for all *.lan services.

What it does

Caddy is the front door to every service in The Hold. It listens on port 80 and 443, routes traffic to the correct Docker container based on the hostname, and handles TLS automatically using its built-in Certificate Authority. Every .lan hostname you access goes through Caddy first.

Because Caddy manages its own local CA, you only need to trust one certificate (the root CA) and every service automatically gets a signed cert — no more browser warnings.

How the routing works

The Caddyfile maps each hostname to a Docker container's internal address. For example:

pihole.lan { reverse_proxy pihole:80 } photos.lan { reverse_proxy immich-server:2283 } books.lan { reverse_proxy calibre-web:8083 }

Docker's internal DNS resolves container names, so Caddy uses the service name defined in docker-compose.yml as the target.

Local CA & Certificate

Caddy generates a local root CA on first run, stored in /data/caddy/pki/authorities/local/. The certificate you download from the Certificate section is this root CA. Once trusted by a device, all *.lan sites show a green padlock.

Tip: If you regenerate the CA (e.g., after a data wipe), you'll need to re-download and re-trust the certificate on all devices.

DNS requirement

For *.lan hostnames to resolve, Pi-hole must be set as the DNS server on each device (or via your router's DHCP settings), and custom DNS records must be added in Pi-hole pointing each hostname to the Pi's IP address.

# Pi-hole Local DNS Records (Settings → Local DNS → DNS Records) thehold.lan → 192.168.1.x pihole.lan → 192.168.1.x photos.lan → 192.168.1.x # ... one entry per service

Useful paths

Config: /etc/caddy/Caddyfile Data/Certs: /data/caddy/ Logs: docker logs caddy -f
