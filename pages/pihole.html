Pi-hole

Network-wide DNS-based ad blocker. Blocks ads, trackers, and malicious domains for every device on the LAN.

↗ Open Pi-hole Admin

What it does

Pi-hole acts as a DNS sinkhole for the entire network. When any device makes a DNS request for an ad-serving or tracking domain, Pi-hole returns a null response instead — the ad simply never loads. Unlike browser extensions, Pi-hole works on every device: smart TVs, phones, IoT devices, game consoles — anything on your network.

Key features in use

  • Blocklists — multiple community-maintained lists covering ads, tracking, malware, and telemetry domains.
  • Local DNS — resolves all *.lan hostnames to the Pi's IP address so Caddy can route them.
  • DHCP — optionally serves as DHCP server so all devices automatically get Pi-hole as their DNS.
  • Query log — real-time view of every DNS query on the network with allow/block controls.

Setting Pi-hole as your DNS

The easiest method is to set it at the router level so all devices automatically use it:

Router DHCP Settings → DNS Server → 192.168.1.x (your Pi's IP)

Alternatively, set it per device in the network settings. On iOS: Settings → Wi-Fi → tap your network → Configure DNS → Manual → add the Pi's IP.

Important: You must use Pi-hole as DNS to resolve *.lan hostnames. Without it, all the Caddy-proxied services will be unreachable by name.

Adding local DNS records

Add one record per service so hostnames resolve to the Pi (where Caddy is listening):

Pi-hole Admin → Settings → Local DNS → DNS Records Domain IP ────────────────────────────── thehold.lan 192.168.1.x pihole.lan 192.168.1.x abs.lan 192.168.1.x books.lan 192.168.1.x notes.lan 192.168.1.x cloud.lan 192.168.1.x sync.lan 192.168.1.x photos.lan 192.168.1.x draw.lan 192.168.1.x spacedeck.lan 192.168.1.x

Temporarily disabling

If something is being incorrectly blocked, you can pause Pi-hole from the admin dashboard for 5, 30, or 300 seconds without stopping the container. A whitelist entry is usually a better long-term solution.
